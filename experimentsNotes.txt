EXPERIMENT 1 : How does removing colour information affect the retrieval performance of a pretrained VPR model when the network architecture is kept unchanged?
---------------
RGB vs grayscale copied to 3 channels
-----------------------------------
Evaluated a pretrained CosPlace model with a ResNet18 backbone on the St Lucia dataset using two input conditions: 
the original RGB images and grayscale-converted images replicated across three channels. 
The grayscale replication preserved the original 3-channel input shape expected by the pretrained network, 
ensuring that the model architecture, pretrained weights, image dimensions, dataset, and 
evaluation procedure remained unchanged. Retrieval performance was measured using Recall@1, Recall@5, Recall@10, and Recall@20.

Input	    R@1	     R@5	    R@10	  R@20
RGB	    98.8%	    99.6%	    99.9%	  100.0%

Grayscale	98.6%	     99.5%	     99.8%	   99.9%

Difference	−0.2 pp	 −0.1 pp	 −0.1 pp	−0.1 pp

On St Lucia, CosPlace–ResNet18 maintained nearly identical VPR performance when 
RGB images were converted to grayscale, with Recall@1 decreasing from 98.8% to 98.6%. So removing colour
had a negilible effect.

COMMAND TO RUN EXPERIMENT 1
python3 main.py \
    --method=cosplace \
    --backbone=ResNet18 \
    --descriptors_dimension=512 \
    --database_folder=../VPR-datasets-downloader/datasets/st_lucia/images/test/database \
    --queries_folder=../VPR-datasets-downloader/datasets/st_lucia/images/test/queries \
    --input_mode=grayscale

EXPERIMENT 3 :  Does native 1-channel grayscale reduce peak GPU memory usage during CosPlace–ResNet18 inference?
-------------

baseline_memory = torch.cuda.memory_allocated() -GPU memory before inference
├── CosPlace–ResNet18 weights
├── BatchNorm buffers
├── current query image
└── any other live GPU tensors

Baseline memory: GPU tensor memory already occupied before the forward pass.
Peak memory: highest GPU tensor memory reached during the forward pass
Extra forward memory: how much the memory increased from baseline to that peak.
peak memory - basically telling you how high GPU tensor memory climbed during that inference.

torch.cuda.reset_peak_memory_stats - start watching for the highest memory usage

At the end of the forward pass, memory might only be: 104 MB
but at some point during the computation it reached 128 MB
That 128 MB is what we mean by peak memory.

Input	    R@1	        Mean latency	      Peak GPU memory	             Extra forward memory          Baseline Memory
RGB	     98.8%	          7.308 ms	           92.832 MB	                         37.5 MB            55.332 MB
Native 
grayscale	98.8%	           5.731 ms	            91.292 MB	                          37.5MB             53.792 MB

The baseline gets slightly smaller with grayscale, but the additional memory required by the forward computation is essentially unchanged.
That makes sense because after the first convolution both networks become very similar as the  intermediate activation sizes through most of ResNet18 are the same.

That means essentially all of the peak-memory saving is coming from what is already 
resident before/during the start of inference, 
rather than from reduced temporary working memory deeper in the network.
That is consistent with the architecture: grayscale has a smaller input tensor and a slightly smaller first convolution, 
but the vast majority of ResNet18 remains unchanged.

Does native 1-channel grayscale require less GPU energy per image than RGB for VPR descriptor extraction?

Input mode	Channels	R@1 (%)	Mean GPU latency (ms)	Peak GPU memory (MB)	Extra forward memory (MB)	GPU Energy per image (J)
RGB		 3	       98.8	              7.308	          92.832                     37.5	                    0.175833 J

Native 
grayscale	 1	       98.8		         5.731	           91.292                     37.5	               0.167513 J

Change: 
Gray vs RGB	 —	      0.0 pp	        21.6% lower	      1.7% lower                 0%	                      4.7% lower

The result is actually quite interesting because the different resource metrics don't improve by the same amount:

Recognition: unchanged at R@1.
Latency: substantial improvement, 21.6% lower.
Peak memory: only 1.7% lower.
Extra forward memory: essentially unchanged.
Energy: modest but measurable improvement, 4.7% lower.

That pattern makes sense architecturally. Going from 3 channels to 1 channel 
mainly reduces computation and storage at the input and first convolution. 
After the first convolution, both versions produce the 
same 64-channel feature representation and then follow almost exactly the same ResNet18 computation.

Better results for GPU Energy per image (J)
